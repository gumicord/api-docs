# 実行モデルと寿命

## 実行モデル

- プラグイン毎に独立した実行環境を1組ずつ持つ。他の
  プラグインとは相互参照できない。
- 予算: 無限ループは 100ms で殺す。連鎖は 8ms (超えたら前回出力＋警告)。
  メモリ上限 32MB・スタック 512KB。
- `GUMICORD_SAFE_MODE` が `0` 以外ならプラグインを読まずに起動する。

## パッチ連鎖の7規則

- 走査はボトムアップ (子→親)。
- 照合は適用前の安定 ID に対して行う。
- 出力には再帰しない。出力は最終形。
- 同一ノードの複数パッチは登録順に連鎖する。
- 例外のノードは適用前に戻す。他へ波及しない。
- プラグインは読込順に連鎖する。前の出力が次に入る。
- パッチは純粋関数。副作用禁止 (呼ばれる回数は不定)。

出力に再帰しない規則がないと無限再帰する。包んだ子が再び同じ ID に
一致し、包み続けるとスタックが尽きる。子を先に片付けておけば、自分に
当てた後に走査するものは残らない。

適用前の ID で照合する理由: 出力の ID で照合すると、当たる集合が実行順に
依存する。適用前の ID で照合すれば、集合は木の形だけで決まる。

プラグイン境界を越えるときは部分木ごと次へ渡すため、後のプラグインは
前の出力全体を走査する。前の挿入物に後のパッチが当たるのは意図した
挙動である。

## 動きの順序

表から見た一生:

1. フォルダに入れると起動時に見つかり、読み込まれる。
2. 能力付きは初見で承認窓が出る。許可するまでその権限は無いものとして動く。
3. 以降は画面が描かれるたびパッチが走る。重い処理は書けない (100ms で殺される)。
4. 壊れ続けると自動で無効化され、通知される。設定画面から有効化し直せる。
5. 拒否したものは読み込まれない。考え直したら設定画面で承認し直す。

## 失敗の数え方

- 失敗は枝に戻して数え、60 秒に 100 回で無効化し、通知する。
  設定画面から有効化し直せる。
- 1 回目は当該ノードのみ元に戻し、記録に残す。
- ホストが受け取れない出力を返したときも1回と数える。未知の安定 ID や
  壊れた形は、そのフレームのそのプラグインの出力ごと捨てて適用前の
  部分木を使い、失敗として記録する。部分的に直すと、どの部分が生きて
  いるか予測できなくなる。
- 壊れたパッチの失敗はフレーム単位で起きるため、100回/60秒は壊れたものを
  2秒以内に止め、散発の失敗には当たらない。
